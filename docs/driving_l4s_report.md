## 关键机制修复汇总（本次迭代）

1. **时钟校准（max-filter + 条件 rtt/2）**：offset 不再被握手重传/排队污染——P50/late 恢复真实（无 L4S 感知恢复的前提）
2. **pacer_limited 持续化（token<0 每心跳设置）**：本地令牌不足时 late/loss 是伪信号，不判拥塞——解贷款死锁
3. **双模式排空**：降幅 >60%（CE ×0.30/×0.20）→ fast（清队列+新 IDR 破产清算，债务清零）；20%~60% → slow（3s Q 面积法）；<20% 平滑处理
4. **fast 冻结期**（触发+3s = 排空+锁定）：关键帧超发 CE 豁免并入冻结期（IDR 提交时延长）；冻结内 btl 完全冻结（不降不爬）
5. **late/delay 柔降表**（0.90/0.75/0.65/0.50 vs CE 急表 0.65/0.45/0.30/0.20）：软信号（迟到/排队含追赶成分）温和降速，硬信号（CE 真实超发）急降
6. **overload 判定 EWMA 平滑**：IDR 突刺的报告窗口错位（send/recv 分属两窗口）不再误判持续超发
7. **CE 最小样本门槛**（<20 报文不判）：发送受限期 CE 尾流被小分母放大虚高的问题消除
8. **proxy 纯带宽积压指针（bw_drain）**：delay-normal/reorder 的正常延迟仿真不再污染带宽队列积压——CE 只由真实带宽排队触发（修复 40-52s 渐变段 CE 误触发根源）
9. **probe 起步校准**（set_seed_and_clamp）：握手测速结果钳制 btl 不超链路（弱网起步不再 30M 硬塞）；不锁种子（恢复爬升自适应链路变化）

## 结论

1. **无 L4S 网络完全达标**：drop 1、underrun 0、连续播放无断流、零排空/贷款循环——时钟校准 + pacer 持续化 + 柔表让发送端在纯 late/loss 信号下也能温和收敛
2. **有 L4S 网络达标**：underrun 0、零循环、恢复段稳定爬升；CE 真实超发时急降收敛、CE 误触发（delay 污染/小样本/IDR 突刺）全部消除。残余 drop 19 主要来自 0-20s 偶发"停等关键帧"（QSV 编码器侧偶发，与拥塞控制无关）
3. **L4S 的价值**：让发送端在队列积压（而非丢包/迟到）时提前降速——CE 是唯一不依赖发送端状态的客观链路信号；无 CE 网络靠 late（时钟校准后真实）+ 柔表同样收敛
4. **恢复段爬升**受 recv_rate×1.2 约束（防跳帧后爬满格超发）——60s 内收敛 3-6M 稳定不崩；链路长时间恢复时可继续爬升
