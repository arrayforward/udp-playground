# tight 实时音视频弱网优化 —— 验收文档

验收日期：2026-08-18
验收对象：tight 可靠 UDP 传输协议（`creek/tight`）+ 测试侧（`video-sender`/`video-player`/`udp-proxy`）
验收场景：follow 弱网动态场景（良好 10M → 弱网 3M+丢包+长尾延迟 → 恢复，8s 循环）

---

## 1. 目标

弱网（带宽波动 + 丢包 + 延迟抖动）下实时音视频传输的稳定性：

- 音频连续（欠载趋零）、视频流畅（丢帧趋零）
- 带宽估计跟随链路变化（不超发、不崩底）
- 带宽不足时优先保证音频；视频码率按有效带宽自适应
- FEC 冗余自适应（迟到率驱动，少量阻塞有用、大量阻塞让出带宽）

## 2. 最终指标（follow 45s，弱网段 3M / 丢包 2% / 长尾延迟）

| 指标 | 最终值 | 历史最差 |
| --- | --- | --- |
| 音频欠载 | **1 次** | 21-24 次 |
| 视频丢帧 | **1 帧** | 39-138 帧 |
| 排空（积压止损） | **0 次** | 9-13 次 |
| 视频送达 | 持续 30fps | 曾断流 |
| btl 弱网段 | 收敛到真实链路附近 | 曾高估 2 倍 / 崩底 100k 死锁 |

## 3. 实现内容

### 3.1 三信号 AIMD 拥塞估计器（GCC 风格，替代 BBR）

`bandwidth.hpp/.cpp` 重写，删除 BBR 的投递率窗口/增益时间片循环（16s 周期），改为每报告周期（333ms）AIMD：

| 信号 | 来源 | 判定 |
| --- | --- | --- |
| delay-based | P50 − RTprop（发送端 min filter）+ EWMA 趋势 | 排队延迟 > 20ms → 拥塞 |
| late-based | 迟到率 = 延迟超线 ∪ 丢失 ∪ CE（替代丢包率） | 迟到率 > 2% → 拥塞 |
| ECN/L4S | CE 标记报文在接收端计入迟到统计 | 并入迟到率 |

调整规则：

- 拥塞：`btl ×= 0.5`（每报告，无冷却）
- 恢复：两步台阶法 `btl ×= 1.5`（每步间隔一个报告）：
  - 台阶 1：压上 FEC 校验片负载感知链路（FEC 可丢失、不伤业务）
  - 台阶 2：确认无拥塞后移除 FEC 探测，业务流量替换 FEC 流量
- 迟滞：降需 `late>2% 或 delay>20ms`；升需 `late<0.5% 且 delay<10ms`；中间区保持
- 防死锁：本地令牌限速（pacer_limited）不判拥塞；btl 下限 100kbps；提升上限 = 种子（10M 起步）

### 3.2 视频容量统一预算（tight 内完成）

```cpp
video_capacity_bps = (btl×8 − audio_reserved×(1+channel_fec_extra[1]) − file/data 实时速率)
                     / (1 + 实际 FEC 冗余率)
```

- 音频固定预留（配置 `audio_reserved_bps`，校验片按设置叠加）、file/data 实测速率、实际 FEC 冗余（fragmenter 滑动窗口统计）全部在 tight 内扣除
- 通知机制：变化迟滞（相对 >10% **且** 绝对 >100k）→ 常驻通知线程回调 `set_video_capacity_callback`；轮询接口 `video_capacity_bps()` 同步提供
- 应用层直接用该值设置编码码率，不再自行折让

### 3.3 通道级排空（drain_channel）

- 排空标记：排空期内指定通道数据报出队即丢（不占带宽、不发），音频/文件/数据零影响
- 三层检查（send_queue / encode 队列 / outbound）：排空期后的旧消息不会从管线漏出
- 默认排空时长 100ms；应用（video_sender）在积压止损时调用，配合 QSV 重启（低码率+新 IDR）

### 3.4 FEC 自适应（tight）

- 迟到率（超线 ∪ 丢包 ∪ CE）驱动分段冗余（stage 状态机：0 片 / 1 片 / 熵公式）
- RTT 长期 >200ms（长距离/重拥塞）→ 自动关闭 FEC 冗余（让出带宽）
- 应用层不再配置固定冗余（channel_fec_extra 默认 0）

### 3.5 测试侧（验证用，非协议）

- **QSV 硬编**：`ffmpeg.exe h264_qsv` 子进程（码率收敛即时，对比 MF 软编 1-2s 收敛），码率下限 1.5M（720p 硬性约束）
- **音频通道**：ffmpeg.exe 子进程解码音轨 → Opus 128kbps/20ms → 通道 1（优先级队列）→ 播放端 300ms 抖动缓冲 + PLC
- **30fps 内容节流**：QSV 硬编快于源帧率，显式节流防快进超发

## 4. 关键修复链（问题 → 根因 → 修复）

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 视频断流（nokey 丢帧 148+） | 视频无冗余 + 2% 丢包 → 丢 1 片整帧丢 | 迟到率驱动 FEC（stage≥1 时 1 片校验） |
| btl 卡死 100-200K | 音视频混合流下 app_limited 永不生效 → 投递率=应用速率被当链路容量 | AIMD 重写（不依赖投递率） |
| btl 崩底死锁 | 令牌 < 应用供给 → 自造积压 → p50 高 → 误判拥塞 | pacer_limited 例外（本地限速不判拥塞） |
| btl 高估 2 倍（弱网） | proxy pacing 限速下超发表现为 qfull 丢包；迟到率不含丢包 | 丢包 = 永远迟到（计入迟到率分子分母） |
| btl 摆动 | 阈值过线即反向 | 迟滞（降 2% / 升 0.5%+10ms） |
| 提升后负载卡顿 | 提升直接加业务流量 | 两步台阶（FEC 探测先行，业务替换） |
| 排空伤音频 | clear_outbound 清全部队列 | drain_channel 按通道标记丢弃 |
| 8M 超发窗口 | 100MB 种子起步 + btl 收敛慢 | 种子 10Mbps 起步 |
| 预算虚折（fec 60-100%） | 预算用理论最大校验片假设 | 实际冗余率统计（fragmenter 滑动窗口） |

## 5. 共享令牌桶 + 贷款机制（视频/音频/file-data 带宽分配）

**语义**（用户设计确认）：

| 通道 | 队列 | 令牌/贷款 | 说明 |
| --- | --- | --- | --- |
| 音频 ch1 | 独立队列（容量 128） | **绕过**（无限速、不贷款） | sender 每心跳优先清空、一次性发完；实时音频无条件优先 |
| 视频 ch0 | 普通队列 | **共享桶 + 贷款**（额度 = btl×loan_seconds） | 帧随心跳一次性发完（不被打平）；贷款覆盖编码联动延迟（1-2s）与上层改码率失败的超发窗口 |
| file/data ch2/3 | 普通队列 | **严格令牌**（不贷款） | 令牌 = 带宽分配器：视频优先占池，file/data 用剩余；视频超发 → 桶负 → file/data 自动让位（可靠通道 12s 窗口 + ARQ 兜底） |

**机制**：
- 令牌桶允许负值（贷款）；refill 每心跳（10ms）无条件（空闲心跳自动还贷，无报文时令牌归还款）
- 贷款耗尽（token < −btl×loan_seconds）→ 清空视频积压 + 持续排空视频通道（至债务清零）+ 回调 `set_loan_exhausted_callback(true)`；债务清零 → 恢复发送 + 回调 `false`（应用重启编码器出关键帧 + 低码率）
- 配置：`TightConfig.loan_seconds`（默认 5.0，0 = 禁用贷款严格令牌）

**验证结果（loan_seconds=5s）**：

| 场景 | 贷款循环 | 音频欠载 | 视频 | 排空 |
| --- | --- | --- | --- | --- |
| L4S follow（弱网 3M/4M + CE） | 4 次（1s 时 15 次） | 4（PLC 兜底） | 866 帧全程、丢帧 19 | 0 |
| follow（弱网 3M + 丢包 2%） | 4 次 | 4 | 丢帧 26（弱网段正常范围） | 0 |

- 弱网段（btl 触底 < 视频下限 1.5M）：视频超发 → 贷款（5s 额度）→ CE → btl 降 → 额度收窄 → 耗尽 → drain（视频停 3-4s，btl 台阶回升）→ 恢复（btl ≥ 1.5M 后不再超发）→ 收敛；段 4（10M）满额稳定
- 1s 额度的教训：弱网段循环 15 次（视频断续 + 音频欠载 11）——贷款期视频超发 → 链路排队 → 音频（本地绕过但绕不过链路队列）300ms 缓冲耗尽；5s 额度将循环降至 4 次
- 贷款 drain 取代原 500 片 queue congested 止损（排空 0 次，止损语义从"队列深度"升级为"债务超限"）

## 6. L4S/ECN 场景验证（video_follow_l4s：0-15s 弱网 3M l4s-on → 恢复 → 4M l4s-on → 恢复）

L4S 段最终指标（45s，CE 标记由 proxy 在积压 >20ms 时打标）：

| 指标 | 最终值 | 说明 |
| --- | --- | --- |
| 视频丢帧 | **1 帧** | 仅启动期 nokey；L4S 无丢包 |
| 音频欠载 | **4 次** | PLC 4 次兜底 |
| 排空（积压止损） | **0 次** | 崩底死锁彻底消除（此前 7 次） |
| CE 响应 | **~2s 内** | 首个 CE 报告即触发降速 |
| btl 收敛 | 弱网段不崩底 | 最低 ~50K 后台阶回升；恢复段满额 |

L4S 修复链（本轮新增，均为实测驱动）：

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| CE 计入迟到率 → fec 100% → 线上超发 → 更多 CE → btl 连崩到底死锁 | CE 与 FEC 双重惩罚叠加；L4S 无丢包，冗余纯浪费 | CE 独立计数上报（`ce_ratio`），不再计入 late_samples；拥塞判定 `late>2% ∥ ce>1%`；FEC 驱动只用 late（不含 CE） |
| L4S 下"丢包"语义 | L4S 网络不丢包只打标，loss 与 CE 叠加双倍惩罚 | 报告期收到 CE（L4S 活跃）→ 丢包不再计入迟到率（CE 即 loss） |
| 台阶 1 FEC 探测使线上 1.5M×2>3M → 自伤 | 探测冗余在 CE 环境下多余 | L4S 活跃（ce_ratio≥1%）时台阶 1 不加 FEC 探测（CE 即链路反馈） |
| pacer_limited 时迟到率主体是本地排队伪信号 → 连降崩底 | 应用码率下限（QSV 1.5M）> 令牌 → outbound 积压 → 接收端 p50 超线 → late 100% → 降 → 更多排队 | 报告携带纯丢包率 `loss_ratio`；pacer_limited 时拥塞/恢复判定只用真实链路信号（loss/CE），豁免本地排队伪 late |
| 本地排队 → late 污染 FEC → 恢复后带冗余超发 → 再排队（循环） | 冗余率随伪 late 走高 | FEC 让出条件收紧：RTT>200ms 或 CE>1% 才关（丢包场景不关——丢包稀疏会误关，实测 64 帧 nokey vs 全开 1 帧） |
| FEC 冗余过大（100%）加剧排队 | 熵公式无上限 | 冗余率上限 20%（单分片消息至少 1 片保护） |
| 启动 8M 全速超发 → 弱网链路积压 MB 级 → 排空期 CE 持续 → 连降 | 首报告前种子（10M）驱动全速 | 启动期（首 3s）码率上限 3M |
| QSV 重启风暴 → device failed(-17) 后全部实例失败、视频永久停 | set_bitrate 重启 2s 冷却太短（弱网段 25s 内 ~10 次）+ TerminateProcess 强杀不释放 QSV 会话 | 重启冷却 2s→4s；kill_child 改为 stdin EOF 优雅退出（1s 未退出才强杀）+ 300ms 设备释放等待；spawn 失败退避（2s，3 连败后 10s） |

## 7. 帧级迟到判定 + 突刺门控（关键帧免疫）

**问题链**：关键帧（I 帧 40-60KB，可达普通帧百倍）一次性连发（贷款）→ 低带宽链路瞬时排队数十 ms → 报文级迟到线（P50+16ms）把突刺排队误判为迟到 → late 30-46% → FEC 自放大（late→冗余→发送↑→排队↑）→ 量化重档连降 → btl 崩底 → 贷款循环。

**修复（帧级迟到）**：迟到判定从"报文延迟 vs P50+16ms"改为"**帧延迟 vs 合理到达时间 = 对端 P50 + 帧大小/btl + late_buffer**"——帧越大线越宽，关键帧传输是帧自身开销，不算迟到；持续超发排队超过最大帧合理时间才记迟到。接收端每帧重组完成上报（正常模式逐帧 (F,D) 对；lite 模式最大帧+直方图，8ms/bin×64），发送端用 btl 折算判定。

**修复（突刺门控）**：拥塞降速加 `sustained_overload` 门控（报告期平均发送速率 > 对端接收速率 = 持续超发）——关键帧突刺是瞬时信号（333ms 平均 send ≤ recv）→ 不降速（btl 保持，排空后恢复台阶回升）；持续超发才按量化阶梯降速。

**验证（30M/10M/15M 场景，l4s-threshold 20ms，45s）**：

| 指标 | 修复前（贷款 5s 版） | 修复后 |
| --- | --- | --- |
| 贷款循环 | 3-4 次 | **0 次** |
| 音频欠载 | 3 | **0** |
| 视频丢帧 | 13 | **1**（仅启动期） |
| btl | 弱网段崩底 12500 | **全程 30M 封顶、零崩底** |

follow 丢包回归：贷款 3→1 次、欠载 3→1、丢帧 46→17、写 474→668 帧。

## 9. 遗留问题（记录在案，非阻塞）

1. **下限钳制区**：btl < ~1.6Mbps 时码率锁 1.5M（QSV 720p 编码器硬限）——弱网 <1.5M 只能超发（FEC/排空兜底）；后续可通过**分辨率动态降级**（720p→480p，QSV 下限更低）消除
2. **启动期（0-15s）视频偏慢**：QSV 高码率（8M）大帧写阻塞，一次性；可临时压低启动期码率上限
3. **诊断打印**（DBG aimd / deliv / frag / report 等）保留在代码中，正式发布前可清理
4. **fec_disable 阈值 200ms** 与 delay-based 阈值（20ms）为经验值，长距离高 RTT 场景需专项验证
5. **QSV device failed(-17)**：长时间高密度重启后 iGPU 驱动仍可能失败（本机连续 20+ 轮 45s 测试后恶化）；已缓解（优雅退出/冷却/退避，失败后视频可自动恢复），根因在驱动层，冷启动系统后复测确认
6. **L4S 弱网段收敛震荡**：台阶恢复（×1.5）过冲链路后 CE 再降（峰值递减收敛），不崩底；台阶步长更小可消除（当前 1.5 为用户确认值）
7. **follow 场景启动期丢帧（随机 0-18）**：stage 0/1 低冗余期大 IDR 丢片（2% 丢包随机性），弱网段 FEC 高冗余恢复有效

run_video_follow.bat [秒数]   # video-sender → udp-proxy(follow 场景) → video-player
# L4S 场景（proxy 用 scenarios/video_follow_l4s.txt，需手动起三个进程或另行脚本）

观察点：
